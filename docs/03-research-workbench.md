# 开发文档 03｜研究工作台与可视化交互

面向专业研究员的可研究、可验证、可下钻 UI 规格

文档版本：v0.2  |  日期：2026-08-05  |  状态：MVP Engineering Baseline

| 关键决策：界面不是“舆情大屏”，而是研究工具。每个视觉结论必须可下钻到证据；每个研究结论必须能看到时间、来源、样本量、算法版本与置信度。 |
| --- |

## 1. 设计目标

- 30 秒内判断：是否有新事件值得研究。

- 3 分钟内理解：市场在争论什么、主要观点如何变化、可能影响哪些行业和公司。

- 10 分钟内完成：证据抽查、传导链验证、研究笔记与导出。

- 不以“漂亮”为第一目标；优先保证数据密度、可比较性、可追溯性与研究操作效率。

## 2. 页面体系

| 页面 | 用户问题 | 关键组件 |
| --- | --- | --- |
| 风险总览 | 现在有什么值得关注？ | 事件列表、风险筛选、热度变化、关注池 |
| 事件研究工作台 | 这件事是什么、为什么重要？ | 时间线、观点簇、情绪结构、传导图、影响矩阵 |
| 证据检索 | 依据是什么？ | 原文列表、过滤器、引用链、排除/纳入 |
| 实体页 | 某公司/行业近期暴露如何？ | 事件暴露、历史情绪、关联传导 |
| 历史对比 | 类似事件以前发生过吗？ | 事件并排、指标归一化、差异摘要 |
| 报告/导出 | 如何交付研究成果？ | 风险卡片、研究简报、CSV/JSON |

## 3. 风险总览页面

| 区域 | 展示内容 | 交互 |
| --- | --- | --- |
| 顶部状态 | 活跃事件数、高风险数、数据源健康、系统更新时间 | 点击进入过滤视图 |
| 事件队列 | 标题、首次发现、热度增速、净情绪、分歧度、风险等级、事实状态 | 排序、筛选、关注/忽略 |
| 关注池 | 用户关注行业/公司暴露事件 | 固定在顶部或独立标签 |
| 最新告警 | 触发原因、阈值、时间 | 确认、静音、打开事件 |

### 3.1 当前代码边界

- `/` 已实现固定 Demo 上下文的事件总览，展示事件数量、活跃事件、已校准事件、关联原文和事件卡片。
- `/event/{id}` 已实现事件头部、Rule 3/4 评分、文档量时间线、观点归因、传导候选、热力矩阵和证据抽屉。
- 页面读取后端事件、证据、观点、传导和影响矩阵 API；接口失败或产物缺失时显示 degraded / unavailable，不使用浏览器 mock。
- ECharts 已用于时间线与热力矩阵，React Flow 已用于存在传导边时的交互图；当前截图中的传导与影响矩阵为空，表示后端尚无可验证产物或输入不足，而不是渲染故障。
- 筛选、关注池、告警、人工修正和导出仍是目标规格，尚未实现；`AnalysisSnapshot` 与模板报告已接线，LLM 报告 Render 仍未实现。

## 4. 事件研究工作台：推荐布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 事件标题 / 事实状态 / 风险等级 / 数据质量 / 更新时间          │
├───────────────────────────────┬──────────────────────────────┤
│ A. 多指标事件时间线            │ B. 观点簇与情绪结构           │
│ 新闻/帖文/情绪/价格/节点       │ 主导观点、分歧、变化速度       │
├───────────────────────────────┼──────────────────────────────┤
│ C. 传导路径图                  │ D. 行业-公司影响矩阵           │
│ 事件→机制→行业→公司            │ 方向/强度/周期/置信度          │
├───────────────────────────────┴──────────────────────────────┤
│ E. 证据抽屉 / 原文 / 研究笔记 / 导出                         │
└──────────────────────────────────────────────────────────────┘
```

## 5. 时间线设计

- 同一横轴叠加：帖子量、新闻量、净情绪、情绪分歧、目标行业/股票价格或成交量。

- 关键节点必须明确标注“首条消息、媒体确认、官方确认、观点切换、告警触发”。

- 鼠标悬停显示该时间桶样本数与来源构成；点击时间桶打开对应证据。

- 对缺失或延迟数据使用断点/阴影提示，禁止通过插值伪造完整实时性。

- 价格与情绪同图只表示时间对齐，不在 UI 文案中自动宣称因果。

## 6. 观点簇面板

| 字段 | 说明 |
| --- | --- |
| 观点标题 | 由 LLM 对聚类后的观点做短句命名 |
| 目标对象 | 行业/公司/政策/商品/事件本身 |
| 立场 | 看多/看空/中性/观望 |
| 情绪 | 恐慌/期待/怀疑/愤怒/中性等 |
| 独立样本数 | 去重后的有效文本数 |
| 传播量 | 包含转发/引用的扩散规模 |
| 占比 | 在当前事件有效观点中的权重占比 |
| 增速 | 最近窗口相对上一窗口变化 |
| 可信度 | 来源质量 + 模型置信度 + 证据一致性 |
| 反向证据 | 与该观点冲突的观点/事实数量 |

## 7. 情绪结构

必须同时区分“情绪”“投资立场”“情绪对象”。平均情绪值仅是一个汇总指标。核心展示包括净情绪、分歧度、情绪构成和对象分布。

```text
事件本身：负面  -0.72
上游资源公司：正面  +0.48
下游制造企业：负面  -0.61
政策持续时间：高怀疑度 0.67
```

## 8. 传导路径图

- 节点类型固定：Event / Mechanism / Industry / Company / MarketVariable。

- 边必须包含 direction、confidence、evidence_count、status（事实/假设/人工确认）。

- 默认只显示高置信度主干；用户可展开低置信度候选和反向路径。

- 点击边打开“为什么存在这条关系”的证据面板；研究员可确认、拒绝或备注。

- 被人工拒绝的边保留版本历史，后续模型评估可使用。

## 9. 行业—公司影响矩阵

| 列 | 含义 |
| --- | --- |
| 对象 | 行业/上市公司 |
| 方向 | 潜在受益/潜在受损/不确定 |
| 影响强度 | 规则计算后的分档或连续值 |
| 业务暴露 | 事件机制与主营业务关联度 |
| 舆情支持 | 相关独立观点证据强度 |
| 事实支持 | 公告/新闻事实锚定程度 |
| 时间周期 | 即时/短期/中期/长期 |
| 综合置信度 | 由确定性公式聚合，不由 LLM 直接给最终分 |

## 10. 证据层：专业工具的核心

- 支持来源、平台、时间、实体、观点、立场、情绪、是否重复、可信度过滤。

- 原文旁显示“被哪些观点/传导边/摘要句引用”。

- 支持“纳入分析 / 排除样本 / 标记错误 / 添加研究备注”。

- 所有人工操作应即时影响下一轮聚合，但不能覆盖原始文本。

- 研究员可导出当前筛选结果及其元数据，以便外部复核。

## 11. 视觉编码规则

| 维度 | 规则 |
| --- | --- |
| 涨跌/正负 | 文字 + 箭头 + 颜色三重编码，不能只靠红绿 |
| 置信度 | 数值 + 高/中/低标签；低置信度采用虚线/弱化 |
| 事实/假设 | 事实使用实线标签，模型假设明确标记“候选” |
| 数据缺失 | 显式显示缺失/延迟，不用 0 代替 |
| 样本量 | 关键比例必须旁显 N |
| 时间 | 统一时区且显示精确时间，支持相对时间作为辅助 |

## 12. 研究操作与版本化

| 操作 | 系统行为 |
| --- | --- |
| 确认观点 | 记录 reviewer、时间、原值与确认值 |
| 合并/拆分观点簇 | 生成新版本，不删除历史 |
| 拒绝传导边 | 边状态变为 rejected_by_user |
| 调整关注对象 | 仅改变用户视图和告警，不修改全局事实 |
| 生成简报 | 冻结当前 snapshot_id，保证报告可复现 |
| 重新分析 | 创建 analysis_version，不覆盖旧结果 |

## 14. MVP 验收标准

1. 风险总览可按风险、行业、时间和关注池筛选事件。

1. 事件工作台一屏内同时展示时间线、观点簇、传导关系和影响对象。

1. 任一图表点/观点/传导边可在两次点击内打开对应原始证据。

1. 用户可排除一条错误样本并看到聚合结果在下一版本中更新。

1. 报告生成时保存 snapshot_id，之后即使数据更新仍可复现当时报告。
