# 开发文档 01｜平台形态与部署架构

金融事件—社交情绪—市场传导实时量化与预警分析平台

文档版本：v0.1  |  日期：2026-08-04  |  状态：MVP Engineering Baseline

| 关键决策：主产品采用桌面端 Web SaaS；移动端仅承担告警与轻量查看；机构客户的本地客户端/私有化部署作为后续企业能力。 |
| --- |

## 1. 文档目标与范围

本文定义产品载体、用户角色、前后端边界、部署模式、通知入口、非功能要求与 MVP 验收标准。本文不定义消息源清洗算法、LLM 提示词或具体可视化指标公式，这些分别由其他开发文档约束。

## 2. 平台决策

| 平台 | MVP 决策 | 用途 | 备注 |
| --- | --- | --- | --- |
| 桌面 Web SaaS | 必须 | 完整研究工作台、配置、下钻、导出 | 核心产品形态 |
| 手机 Web / PWA | 建议 | 事件卡片、告警详情、快速关注/忽略 | 复用 Web 代码 |
| Android / iOS 原生 App | 不做 | — | MVP 成本高，专业研究场景弱 |
| Windows/macOS 客户端 | 后续 | 内网数据源、本地终端集成 | 机构私有化需求出现后再做 |
| API / Webhook | 必须预留 | 对接内部研究系统、机器人、告警渠道 | 接口优先设计 |
| 私有化部署 | 架构兼容 | 机构版 | 不作为黑客松交付项 |

## 3. 用户角色与权限

| 角色 | 核心任务 | 主要权限 |
| --- | --- | --- |
| 研究员 Researcher | 发现事件、验证证据、分析传导、导出研究材料 | 查看与修改研究标签、保存笔记、导出 |
| 团队负责人 Lead | 关注重大风险、审核研究结论、配置团队关注池 | 审批、订阅、团队模板、共享研究 |
| 管理员 Admin | 管理成员、数据源、模型与系统配置 | 租户、权限、配额、数据源、审计日志 |
| 系统服务 Service Account | API 调用与自动推送 | 最小范围 Token 权限 |

## 5. 前端技术边界

- 推荐栈：Next.js / React + TypeScript。所有核心页面支持 1440px 宽屏研究场景，同时兼容 1024px 笔记本。

- 状态策略：实时数据采用 Server-Sent Events 或 WebSocket；查询与过滤通过 REST/JSON；前端不计算权威风险分数。

- 数据下载：大结果集使用后端异步生成导出文件，前端只显示任务状态与下载入口。

- 可追溯性：任何图表点、矩阵单元格、摘要句都应能带 evidence_id / calculation_id 下钻。

## 6. 后端服务划分

| 服务 | 职责 | MVP 实现建议 |
| --- | --- | --- |
| API Gateway / BFF | 鉴权、租户隔离、聚合前端接口 | FastAPI 单体模块化实现 |
| Ingestion | 数据接入、原始数据落库 | 后台 worker |
| Event Engine | 去重、聚类、事件状态、热度异常 | Python 服务 |
| Analysis Orchestrator | 调用传统模型/LLM、管理任务状态 | 任务队列 + worker |
| Scoring Engine | 情绪/热度/风险等确定性计算 | 纯函数 + 版本化参数 |
| Evidence Service | 原文、来源、引用链 | PostgreSQL + 对象存储 |
| Notification | 告警路由、去重、升级 | 后台 worker |
| Report Service | 简报生成与导出 | 模板 + LLM 受限生成 |

## 7. 基础设施与环境

| 组件 | MVP | 扩展阶段 |
| --- | --- | --- |
| 关系数据库 | PostgreSQL | PostgreSQL + 读副本/分区 |
| 缓存/任务队列 | Redis | Redis + 专用消息队列 |
| 对象存储 | S3 兼容对象存储 | 生命周期与归档策略 |
| 实时消息 | SSE/WebSocket | Kafka/Redpanda + WebSocket Gateway |
| 搜索 | PostgreSQL FTS/向量扩展 | OpenSearch/Elasticsearch |
| 部署 | Docker Compose / 单云环境 | Kubernetes 或企业私有化 |

## 8. 认证、租户与审计

- 所有业务数据必须携带 tenant_id；数据库查询不得依赖前端传入 tenant_id 作为唯一隔离手段。

- 采用 RBAC：Researcher / Lead / Admin / Service Account；敏感配置和导出操作必须记录审计日志。

- API Token 需要 scope、过期时间和可撤销能力；生产环境禁止在前端暴露第三方数据源密钥和模型密钥。

- 研究结论的手动修改必须记录修改前值、修改后值、操作者与时间。

## 10. 非功能要求（MVP SLO）

| 指标 | 目标 |
| --- | --- |
| 页面 API P95 | < 800 ms（不含 LLM 分析） |
| 事件流到 UI 可见延迟 | < 10 s（数据已进入系统后） |
| 单次结构化分析任务 | 目标 60–120 s 内完成 |
| 告警生成 | 规则满足后 < 10 s |
| 核心页面可用性 | 演示环境 99% 以上 |
| 审计覆盖 | 模型调用、风险分数、人工修改、导出 100% 记录 |

## 11. MVP 验收标准

1. 用户可登录并进入风险总览，看到至少 10 个历史回放事件。

1. 点击事件后可进入统一研究工作台，并保持事件数据实时刷新。

1. 每个重要结论可下钻至至少一条原始证据。

1. 管理员可配置一个关注行业/公司列表和至少一条告警阈值。

1. 达到阈值后生成站内告警，并可通过一个外部渠道（邮件/企业微信二选一）发送。

1. 研究员可导出事件数据 CSV 与风险卡片 PDF/HTML（MVP 可先 HTML）。
