# 开发文档 01｜平台形态与部署架构

金融事件—社交情绪—市场传导实时量化与预警分析平台

| 关键决策：主产品采用桌面端 Web SaaS；移动端仅承担告警与轻量查看；机构客户的本地客户端/私有化部署作为后续企业能力。 |

## 1. 文档目标与范围

本文定义产品载体、前后端边界、部署模式、通知入口、非功能要求与 MVP 验收标准。本文不定义消息源清洗算法、LLM 提示词、角色权限体系或具体可视化指标公式，这些分别由其他开发文档约束。

## 2. 平台决策

| 平台 | MVP 决策 | 用途 | 备注 |
| --- | --- | --- | --- |
| 桌面 Web SaaS | 必须 | 完整研究工作台、配置、下钻、导出 | 核心产品形态 |
| 手机 Web / PWA | 建议 | 事件卡片、告警详情、快速关注/忽略 | 复用 Web 代码 |
| Android / iOS 原生 App | 不做 | — | MVP 成本高，专业研究场景弱 |
| Windows/macOS 客户端 | 后续 | 内网数据源、本地终端集成 | 机构私有化需求出现后再做 |
| API / Webhook | 必须预留 | 对接内部研究系统、机器人、告警渠道 | 接口优先设计 |
| 私有化部署 | 架构兼容 | 机构版 | 不作为黑客松交付项 |

## 3. Demo 访问模型

Demo 不实现多角色矩阵，也不建设成员管理、审批流或权限后台。所有页面默认面向一个固定 Demo 研究上下文，重点验证数据导入、事件归类、评分校准、证据下钻、报告和导出链路。

为了避免后续返工，服务端仍应使用固定 demo tenant/context 读取业务数据；前端不得通过任意 `tenant_id` 参数决定数据范围。

## 4. 信息架构与路由

```text
/
├── /overview                 实时风险总览
├── /events/:event_id         事件研究工作台
├── /entities/:entity_id      行业/公司实体页
├── /evidence                 证据检索
├── /compare                  历史事件对比
├── /watchlists               关注池
├── /alerts                   告警中心
└── /reports                  研究简报与导出
```

## 5. 前端技术边界

- 推荐栈：Next.js / React + TypeScript。所有核心页面支持 1440px 宽屏研究场景，同时兼容 1024px 笔记本。

- 状态策略：实时数据采用 Server-Sent Events 或 WebSocket；查询与过滤通过 REST/JSON；前端不计算权威风险分数。

- 数据下载：大结果集使用后端异步生成导出文件，前端只显示任务状态与下载入口。

- 可追溯性：任何图表点、矩阵单元格、摘要句都应能带 evidence_id / calculation_id 下钻。

## 6. 后端服务划分

| 服务 | 职责 | MVP 实现建议 |
| --- | --- | --- |
| API Gateway / BFF | 固定 Demo 上下文、聚合前端接口 | FastAPI 单体模块化实现 |
| Ingestion | 数据接入、原始数据落库 | 后台 worker |
| Event Engine | Rule 1 事件归类、Rule 2 入库管理、事件状态机 | Python 服务 |
| Scoring Engine | Rule 3 确定性评分、Rule 4 后验校准、热度/动量/风险指标 | 纯函数 + 版本化参数 |
| Analysis Orchestrator | 在评分链完成后调用 Agent 1/2、管理任务状态 | 任务队列 + worker |
| Evidence Service | 原文、来源、引用链 | PostgreSQL + 对象存储 |
| Notification | 告警路由、去重、升级 | 后台 worker |
| Report Service | 基于冻结 Snapshot 的报告生成与导出 | 模板 + Agent 2 Render 受限生成 |

## 7. 基础设施与环境

| 组件 | MVP | 扩展阶段 |
| --- | --- | --- |
| 关系数据库 | PostgreSQL | PostgreSQL + 读副本/分区 |
| 缓存/任务队列 | Redis | Redis + 专用消息队列 |
| 对象存储 | S3 兼容对象存储 | 生命周期与归档策略 |
| 实时消息 | SSE/WebSocket | Kafka/Redpanda + WebSocket Gateway |
| 搜索 | PostgreSQL FTS/向量扩展 | OpenSearch/Elasticsearch |
| 部署 | Docker Compose / 单云环境 | Kubernetes 或企业私有化 |

## 8. Demo 上下文与追溯

- Demo 不实现登录、RBAC、API Token scope 或成员管理。

- 业务查询使用服务端固定 demo context；不得依赖前端传入 tenant_id 作为唯一隔离手段。

- 上述 Demo 限定不适用于真实来源写入。统一 ingestion API 使用服务端配置的 Bearer 服务账户，将 token 映射到固定 tenant 和 provider allowlist；请求体不得决定 tenant。当前只实现单个配置化服务账户，生产级账户管理、轮换与细粒度 scope 仍属后续能力。

- 生产环境禁止在前端暴露第三方数据源密钥和模型密钥。

- Demo 阶段如支持人工修改，至少记录修改前值、修改后值和时间；完整多用户审计留到企业版。

## 9. 移动端与通知设计

| 能力 | 移动端 | 桌面端 |
| --- | --- | --- |
| 重大事件告警 | 主入口 | 完整中心 |
| 一分钟风险卡片 | 支持 | 支持 |
| 原始证据深度筛选 | 轻量 | 完整 |
| 传导图编辑 | 不支持 | 支持 |
| 批量比较/导出 | 不支持 | 支持 |
| 配置模型/数据源 | 不支持 | Demo 不支持，后续企业版支持 |

## 10. 非功能要求（MVP SLO）

| 指标 | 目标 |
| --- | --- |
| 页面 API P95 | < 800 ms（不含 LLM 分析） |
| 事件流到 UI 可见延迟 | < 10 s（数据已进入系统后） |
| 单次结构化分析任务 | 目标 60–120 s 内完成 |
| 告警生成 | 规则满足后 < 10 s |
| 核心页面可用性 | 演示环境 99% 以上 |
| 追溯覆盖 | 模型调用、风险分数、人工修改、导出均保留可复核记录 |

## 11. MVP 验收标准

1. 打开 Demo 后可进入风险总览，看到至少 10 个历史回放事件。

1. 点击事件后可进入统一研究工作台，并保持事件数据实时刷新。

1. 每个重要结论可下钻至至少一条原始证据。

1. 达到阈值后生成站内告警；外部渠道可作为加分项，不作为 Demo 必须项。

1. 可导出事件数据 CSV 与风险卡片 PDF/HTML（MVP 可先 HTML）。
